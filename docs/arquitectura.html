Arquitectura de la solución

Del histórico de sesiones de juego a una decisión explicada de recompensa por cliente: dos modelos de Machine Learning, un optimizador con restricción de presupuesto y una capa de IA generativa, con juego responsable como límite duro.

Casino Palacio Real Datos simulados · 100 000 sesiones · 888 clientes 28 · 08 · 2026

Guardrail de juego responsable. Un cliente clasificado como riesgo Alto no entra al optimizador (etapa 4) y la capa generativa (etapa 5) no produce oferta para él: se genera una nota de derivación al protocolo de juego responsable. La ética es una regla del sistema, no una decisión del modelo.

Las seis etapas en detalle

Cada etapa entrega un artefacto concreto y versionado a la siguiente.

1

Fuente de datos

SQL Server — CasinoPalacioReal

Tabla de hechos de sesiones más un modelo estrella de dimensiones. La lógica de features vive en vistas SQL para que sea auditable sin ejecutar Python.

dbo.FctPlayerSession
100 000 sesiones · cliente, máquina, tiempo, apuestas, resultado, puntos, comps
DimCliente · DimMaquina · DimSala · DimCalendario …
Modelo estrella para enriquecer y segmentar
vw_FeaturesCliente · vw_ClientesScoring
Tabla analítica y baseline por reglas, en SQL

entrega → vw_FeaturesCliente (888 filas)

2

ETL y construcción de features

De sesiones a un vector por cliente

Extracción por SQLAlchemy + pyodbc (autenticación de Windows). Si no hay conexión, fallback al CSV y las features se reconstruyen en pandas con la misma lógica. Partición train/test temporal.

data/extract.py
SQL → Parquet · fallback a CSV
features/build.py
Imputación, acotado de outliers (p1–p99), encoding, split temporal

entrega → data/processed/abt_cliente.parquet

3

Modelos de Machine Learning

Riesgo y probabilidad de respuesta

Dos modelos independientes sobre la misma tabla analítica. Gradient Boosting para datos tabulares; la probabilidad de respuesta se calibra porque el optimizador necesita probabilidades reales, no solo un ranking.

models/risk.py
IsolationForest (perfil atípico) + GradientBoosting → Bajo / Medio / Alto
models/response.py
GradientBoosting + CalibratedClassifierCV → P(respuesta) ∈ [0,1] + decil

entrega → NivelRiesgo, RiesgoScore, ProbRespuesta por cliente

4

Optimización

Asignación de recompensas bajo presupuesto

Para cada cliente elegible y cada tipo de recompensa se calcula P(respuesta) · uplift_valor − costo. Se ordena por eficiencia y se selecciona tipo mochila hasta agotar el presupuesto. Baseline de comparación: las reglas de segmento actuales.

optimization/allocate.py
Ranking por valor esperado / costo · corte por presupuesto · topes por segmento
Restricciones
Riesgo Alto: excluido · Riesgo Medio: solo recompensa baja/media

entrega → plan_asignacion.csv (cliente → recompensa)

5

IA generativa · bloques 2 y 3 del diploma

Explicación, oferta y asistente

Un LLM traduce los scores y sus contribuciones a lenguaje claro, redacta la comunicación personalizada, y responde consultas del analista con RAG anclado en las políticas internas.

genai/explainer.py
Score + contribuciones → explicación + oferta + mensaje (JSON). Guardrail para riesgo Alto
genai/rag.py
Chunking → embeddings → índice vectorial → respuesta citada. Fallback explícito si no hay contexto
rag/politicas/
Política de recompensas · protocolo de juego responsable

entrega → fichas explicadas + respuestas del chat

6

Entrega

App de demo

Una demo que el jurado puede operar en vivo: el tablero muestra el resultado de la campaña frente al baseline; la ficha por cliente muestra features, scores y textos generados.

app/streamlit_app.py
Tablero de cartera · ficha por cliente · pestaña de chat con el asistente

entrega → demo funcional + tablero de resultados

Decisiones técnicas

Qué se eligió, por qué, y qué alternativa se descartó.

DecisiónJustificaciónAlternativa descartada
Features en vistas SQLAuditables y reutilizables fuera de Python; el docente las revisa sin correr códigoTodo en pandas · dbt (excede el alcance)
Gradient Boosting en ambos modelosFuerte en datos tabulares, capta interacciones, rápido de entrenarRedes neuronales (poco dato) · solo regresión logística (poca capacidad)
Calibración de P(respuesta)El valor esperado del optimizador necesita probabilidades realesUsar el score crudo (sesga la asignación)
Optimización greedy tipo mochilaSolución buena en milisegundos y fácil de explicarLP/ILP exacto (extensión) · reglas de segmento (es el baseline)
RAG para el chatbotRespuestas verificables y citadas; evita inventar políticas internasFine-tuning (costoso) · LLM sin contexto (alucina normas)
Guardrail como regla duraLa exclusión de riesgo Alto no puede depender del criterio del modeloConfiar solo en el prompt del LLM
Streamlit para la demoPrototipo operable en vivo; rápido de construirFastAPI + frontend propio (más tiempo) · notebook (no es demo)

Cómo se evalúa

Partición temporal: se entrena con los primeros días y se valida con los últimos.

ComponenteMétricas
Modelo de riesgoF1 macro, recall en clase «Alto», matriz de confusión; validación contra reglas expertas
Modelo de respuestaROC-AUC, PR-AUC, Brier (calibración), lift del decil superior
OptimizaciónRetorno esperado de la cartera vs. baseline de reglas · uso de presupuesto · cobertura
IA generativaRúbrica de utilidad y fidelidad · % de salidas conformes a política (RAG groundedness)
NegocioROI incremental simulado · nº de clientes de riesgo Alto correctamente excluidos
